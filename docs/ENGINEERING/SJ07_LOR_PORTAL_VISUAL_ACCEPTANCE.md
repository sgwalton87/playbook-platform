# SJ-07 LOR Portal — Visual Release Acceptance Gate

**User-approved direction:** Premium black/gold/white Playbook portal mockup featuring the **actual** provided dimensional Playbook logo, prominent gold confidential seal, restrained serif/editorial typography, beautifully composed letter previews, clear two-state sealed/unsealed treatment, and consistent mobile/responsive layout.

**Critical distinction:** The generated concept image is not an application screenshot and does not establish shipped features. Existing /recommenders, /recommenders/[requestId], and /scholar/recommendations presently contain functional but largely inline-styled developer screens. They must be redesigned and visually inspected in staging before any production claim of parity.

Acceptance:
1. **Real branding**: Verify repository brand asset against the full user-provided logo with THE PLAYBOOK, PLAYBOOK and RUN IT!, not an unrelated P or generated substitute; obtain approved crisp optimized PNG/SVG with rights and checksum.
2. **Journey**: Scholar request (Inner Circle and external verified path) → recommender verification/submission → owner Vault sealed/open cards → packet reference attachment, same visual language at every step. No synthetic names in production.
3. **Sealed**: Gold Playbook seal on confidential letter cover, only recommender identity/metadata/status revealed. No body preview or accessible content through search, accessibility trees, download or packet JSON.
4. **Open**: Recommender-designated open letters can be read with owner authentication.
5. **Post deadline**: Feature must not appear enabled until recommender consent, immutable server deadline, view-only audited watermark and separate security certification are implemented. Never imply deadline automatically grants access.
6. **Delivery**: No false claims that letters are sent to schools or colleges by attaching a packet reference. LOR sender identity must be verified.
7. **Responsive QA**: Screenshot-based human visual comparison at 390px mobile, 768px tablet and 1440px desktop; keyboard focus, VoiceOver/readability, high contrast, no overflow; test actual authenticated app and rejected/empty states.
8. **No regression**: CI, DB certification, recommendation isolated QA, marketplace, profile recovery, and platform QA must all pass against exact deployment SHA before approval. Preserve production branch and credentials until then.

**Release status: NOT visually certified.** This is a blocking acceptance requirement, not a statement of implementation.
